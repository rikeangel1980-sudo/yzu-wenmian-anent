## 1. 结论摘要

**P04 门禁：PASS（有条件）**。路线明确为 **「自主开发为主 + 组件级复用（MIT/Apache-2.0 宽松许可）」**，不整体复用任何现成平台、不做二次开发式套壳。四项关键 PoC 中三项完成（SQLite、G6、FastAPI 服务），模型网关因无真实 Key 属 D3 人工批准范围，仅完成**降级契约设计验证**，实际外部模型联通判 **NOT_RUN**（不虚报）。

技术风险方面，PoC 抓到两个真实缺陷，均给出处置计划并纳入后续门禁：
1. **G6 版本陷阱**：架构文档与一阶段沿用的是 G6 v4 的 `graph.readData()`，但当前 npm `latest` 已是 **v5.1.1**，该 API 不存在；v5 还强制边唯一（重复边直接抛错）。→ P06/P07 必须以 v5 API 重做图谱适配设计，图谱数据入渲染前强制去重与稳定 ID。
2. **ORM 未安装**：架构建议 SQLAlchemy 2.x + Alembic，但本机当前未安装。→ 采用"SQLAlchemy 可用则用、否则 sqlite3 轻量封装 + 自建版本化迁移"双轨约束，P10 环境初始化时锁定。

## 4. 四条路线比较与推荐

| 路线 | 含义 | 优点 | 缺点/风险 | 适配本项目 | 结论 |
|---|---|---|---|---|---|
| A. 完整复用现成平台 | 用 Dify/Moodle 等整套套壳 | 起步快，自带权限/题库 | 与"从零重构 + 自定义教学链路 + 中文教材 + 严格 AI 治理"冲突；许可证复杂；不满足 P00-A1 | 差 | **否** |
| B. 二次开发 | fork 一阶段或某平台改造 | 复用既有代码 | P00-A1 明确完全排除 wenmian_buddy；一阶段无账号无数据库，改造成本高于重建 | 差 | **否** |
| C. 模块借鉴 + 组件级复用 | 自研业务内核，复用 MIT/Apache 组件（FastAPI/G6/jieba/BM25） | 兼顾可控与效率；许可证干净；契合原生前端 | 需自建业务模型、审计、权限、迁移 | **最佳** | **推荐** |
| D. 完全自主开发 | 连画布/分词都自研 | 完全可控 | 重复造轮子，违背 V1.3「先复用后自研」；质量与进度风险高 | 中 | **否（局部必要除外）** |

**推荐路线：C（组件级复用 + 业务内核自研）**。理由：① PRD 75 项 MUST 覆盖教学全链路，无现成平台能原样满足；② P00-A1 要求从零重构，禁止搬旧代码；③ 候选组件均为宽松许可、活跃维护、可独立替换，符合 NFR-005 可维护性；④ 关键风险已由 PoC 验证（SQLite/G6/FastAPI），非"凭口头结论锁定"。

## 8. 开源合规规则（纳入 P14 发布检查）

1. 引入前记录：仓库 URL、版本 Commit、许可证（SPDX）、依赖许可证、引入方式、修改记录。
2. 只借鉴交互/数据模型也保留研究记录；代码级复用须确认许可证兼容（OPEN-12 待技术负责人确认）。
3. NOASSERTION / 自定义许可证（Dify、pgvector、FFmpeg 特定构建）须人工细读并可引入法务确认，P0 不擅自引入。
4. 依赖版本锁定到具体版本，禁止开发中随意升级主版本（架构 §5.4）。
5. 发布前检查依赖清单与许可证、密钥不入库、审计留痕（P14）。
