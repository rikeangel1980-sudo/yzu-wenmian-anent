### 1.2 一句话结论

> **一阶段把「演示正确性」做到了可复验的程度，但把「课堂可用性」留成了空白。**

三条支撑判断：

1. **技术完成度远高于教学验证度。** 9 页功能、约 3,934 行后端 + 8,845 行前端、33 个接口、42/42 拒答准确率都成立；但「有没有学生因此学得更好」**一条真实数据都没有**（作品介绍 7.2 节如实写明「尚未完成课堂规模化应用的数据采集」）。
2. **一阶段的目标函数是「评审得分」，不是「课堂可用」。** v4.0 原文：「任何不能在 23 天内变成可演示画面的工作，对得分的贡献为零」。因此当时主动删除了学习记录、教师审核台、账号体系——**这些恰恰是真实课堂的必需品**。
3. **存在明确的决策反转，必须写进二阶段依赖判断。** 早期纪要「明确不做」里包含**数据库/账号体系/登录/CSRF/WAF**，而二阶段候选清单里的 A1（迁 SQLite）、A3（教师视图）正是要重做这些。**这不是补 bug，是目标变更导致的需求反转**，见 6.4。

## 2. 需求设计回顾

### 2.1 原始教学需求与痛点

**定位**：面向扬州大学旅游烹饪学院《中国名点》本科课程的**课程专属、可追溯、可复算**教学辅助智能体。目标不是替代教师，而是把教师从重复答疑中释放出来。

| # | 教学痛点（一阶段原始表述） | 对应设计 |
|---|---|---|
| 1 | 工艺过程难以口头传达，教材文字抽象，学生不知「这一步做成什么样算对」 | 分步实训：按教材「制作方法」逐步设问 + 要点级即时反馈 |
| 2 | 班级规模大，个别指导难以覆盖，重复答疑占用课时 | 智能体承担标准化、可重复的答疑与训练 |
| 3 | 实训评价依赖教师个人经验，标准不统一 | 评分要点取自教材原文、课前预生成并缓存，同案例稳定可复现 |
| 4 | 教材理论与实操之间缺少及时连接，做坏了不知坏在哪一步 | 每条回答附「章/节/条目/案例」四级溯源；过程报告定位薄弱步骤 |
| 5 | 配方换算易错、难以验证 | 三种换算模式（按倍数 / 按主料反算 / 按目标总量），结果可当场复算 |

**目标用户与场景**（一阶段设定）：

| 场景 | 使用方式 | 一阶段是否验证 |
|---|---|---|
| 本科课堂讲授 | 教师现场提问，答案与来源投影，学生同步回查 | ❌ 未验证，仅设计 |
| 实验/实训课堂 | 学生按案例逐步作答，即时反馈 | ❌ 未验证，仅设计 |
| 实训备课 | 教师用换算按人数生成投料单 | ❌ 未验证 |
| 实训排错 | 描述现象 → 定位教材工艺环节 + 原文依据 | ✅ 功能可用，未课堂验证 |
| 教学复盘 | 教师依据过程报告归纳共性问题 | ⚠️ 报告已实现，**无班级聚合能力** |

### 2.2 一阶段的目标函数：按评审维度反推需求

评分构成为：教学融合与应用设计 25 + 技术实现 25 + 创新价值 20 + 合规与伦理 15 + 应用成效与推广 15。

> 由此推出一阶段最重要的取舍原则：**「可演示」>「工程完备」**。原文：「技术实现一项的官方表述是『架构合理、可演示、可迭代』——不是『工程完备』。」

这条原则解释了一阶段几乎所有「不做」的决定，也是二阶段最容易踩的坑：**用参赛版架构去承载课堂，会出现系统性缺口，而非零散 bug**。

## 3. 功能设计回顾

### 3.1 总体架构（建设说明书口径）

```
数据层   教材 DOCX → 章节树/案例结构化 → 语义切分 → 知识库/图谱/词典/drills/图片
能力层   检索增强问答 | 分步实训引擎 | 配方换算引擎 | 诊断 | 视觉 | 星图
应用层   9 个功能页（原生 HTML/CSS/JS，无构建步骤），共用一套设计系统
```

- **技术栈**：Python 3.10+ / FastAPI + Uvicorn；依赖仅 5 个（fastapi / uvicorn / pydantic / jieba / requests，requests 仅构建期用）。
- **检索**：BM25 + jieba + 面点领域词典（840 词），**无向量库、无 Embedding、无数据库、无 GPU**。
- **生成**：`LLM_API_KEY` 可选；未配置时自动降级 `extractive_answer()`（教材原文直出，9 处调用）。
- **能力层与应用层解耦**：任一模块可独立替换或下线，是「可迭代」的落点。

| 大模型 | `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` / `LLM_TIMEOUT` | 空（降级 extractive） | 文本生成 |

## 4. 流程设计回顾

### 4.1 知识生产流水线（构建期，非运行时）

```
source/中国名点.docx（精校版，勿改）
   ├─ scripts/parse_textbook.py  → data/parsed/（cases.json 254 / chapters / parse_report）
   ├─ scripts/build_kb.py        → data/kb/chunks.jsonl（2406）/ lexicon.txt / kb_report.json
   ├─ scripts/build_graph.py     → data/kb/graph.json（408 节点 / 1342 边）
   ├─ scripts/build_starmap_data.py → frontend/starmap/graph-data.js（227 / 236）
   ├─ scripts/prebuild_drills.py → data/drills/（204 份，课前预生成）
   ├─ scripts/extract_atlas_images.py / fetch_commons_images.py → 66 张成品图
   └─ scripts/capture_manual_shots.py → docs/manual_shots_web/（43 张说明书截图）
```

**关键设计决策**：整条 OCR 链路被删除，因为「前提是教材没有可读文本」已不成立。教材与脚本解耦，但**840 词词典、181 个 drills、236 条星图关联均与《中国名点》硬绑定**——这是二阶段若做跨课程扩展的最大隐藏成本（见 8.3）。

### 4.2 问答主链路（核心卖点「不编造」）

```
用户提问 q
  → 判据零：域外词闸门（domain_mismatch）→ 拒答
  → BM25 + jieba（840 词典）召回 hits
  → judge_rejection(q, hits)  ← 单一入口，chat / coach/ask / 探针共用
      判据一：coverage < 0.40 或 score < 2.0 → 拒答
      判据二：子问题切分，任一段 coverage < 0.34 → 拒答
  → 同义扩展二次补偿（口语词 → 教材术语，9 条映射）
  → 通过 → build_context(hits) → call_llm(context, q, history)
  → _cite_overflow() 引用越界 → 降级教材原文 + mode='guard'
  → 来源卡片（章/节/条目/案例四级路径，程序拼装）+ 覆盖率徽章
  → 拒答 → 「教学边界通知书」（判定依据 + 最接近内容 + 4 个教材内推荐问法）
```

**三层防护**（README 口径）：① 证据强制引用（越界引用服务端丢弃）② 覆盖率判据拒答 ③ 视觉硬闸门（非面点实物拒评）。

**X1 三层防护**（10-19 补）：词典补 12 个教材实证工艺词（828→840）→ 口语词同义扩展 → `cut()` 空 token 兜底。第三层把判定依据从「分词是否为空」换回「教材是否覆盖」，修掉了「怎么起酥」被误拒而拒答卡推荐位又挂着「起酥原理」的自相矛盾。

### 4.3 单一入口与三项一致性自检

`judge_rejection()` 是拒答判定 + 同义扩展二次补偿的**唯一实现**。历史上曾因探针漏掉二次补偿，测出 15/18（线上 18/18）的失真结果；也曾出现首页与实训追问入口结论不一致。

> 因此 `probe_reject.py` 强制做三项自检：**42 样本准确率 + 接口-探针一致性 42/42 + 入口一致性 8/8**。任一项不通过，准确率视为无效。**这是一阶段最重要的方法论资产，二阶段改动拒答逻辑时必须保留。**

### 4.4 分步实训闭环

```
start(case_id) → 返回首个 drill（设问/标准/评分要点，课前预生成）
  → answer(answer) → judge() 三档 verdict（correct / partial / wrong）
       wrong → guide（案例 + 章 + 第 N 步【阶段】+ 原文前 24 字）  ← X5
  → hint（两层提示，不直接给答案）/ reveal / skip / next
  → 全部完成 → report(sid)：各步表现、提示次数、四维评价、薄弱点
  → 导出 PDF（浏览器打印，@media print 只印报告正文）  ← B2，11-10 新增
  → coach/ask：实训内追问，复用主问答三层防护
```

会话落盘 `data/sessions/*.json`（一会话一文件、每次全量重写）；`_persist()` 写 `updated_at` 与 `finished`；`sweep_sessions()` 按 7 天 TTL 清理内存 + 磁盘。

### 4.5 确定性能力（大模型不参与）

| 能力 | 实现 | 边界 |
|---|---|---|
| 配方换算 | 规则解析 + 四则运算；单位归一、区间取上限、分组、烘焙百分比 | 「适量/少许」原样保留，不臆造数字 |
| 随机抽签 | 从 181 案例程序抽取，记录 `request_id` | 可复现 |
| 引用编号 | 程序核对后还原真实来源 | 禁止模型填写章节页码 |
| 步骤进度 | 前端状态机 locked/current/answered/reviewed/completed | |

### 4.6 多轮对话（A2，一阶段末新增）

- `ChatReq` 新增 `history`；`chat()` 传 `req.history`；`call_llm` 截取由 `[-6:]` 改为 `[-12:]`（最近 6 轮）。
- 前端 `qa/index.html` 的 `ask()` 维护本地 `hist`，每次携带最近 6 轮。
- **红线**：`judge_rejection` 只吃本轮 `q`，历史仅喂给大模型做指代消解。已实测「域外追问 + 域内历史」仍被拒答，未击穿「不编造」。
- **限制**：当前 `llm_enabled=false`（extractive 模式），指代消解的真实收益需配置 Key 才显现；e2e 的 C1b 用例目前只断言「字数增长」，**未断言指代正确性**。

### 4.7 运维与保护链路（10-19～10-22 补）

| 决策 | 一阶段（09-19） | 下一阶段方案（11-05） | 性质 |
|---|---|---|---|
