## 2. 架构原则

1. **模块化单体优先**：一个 FastAPI 应用承载模块，P0 不引入微服务/容器编排。
2. **业务模型先于组件**：知识节点、题目版本、提交记录不依赖 G6 或任何模型厂商。
3. **业务规则在服务端**：权限、审核状态、试卷快照、成绩确认、引用校验不依赖前端。
4. **原始资料与衍生数据分离**：教材 DOCX、原始视频/图片为源文件；索引、缩略图可重建。
5. **AI 输出默认不可信**：结构校验 + 来源校验 + 权限过滤 + 人工审核后才可发布。
6. **确定性计算优先**：配方换算、总分、计时、成绩汇总由程序完成，不交给模型。
7. **状态可追踪**：上传、AI 任务、题目审核、关系审核、考试发布、成绩确认均有显式状态机与审计（见 §3.4）。
8. **本机可恢复**：数据库、资源文件、配置、知识构建资产纳入备份/恢复。
9. **不为新颖增加依赖**：每个新组件必须对应明确 PRD 需求与验收收益。
10. **风格单一来源**：师生共用一套 A 设计 token；角色只改变导航条目与业务内容。
11. **身份双层**：学号仅用于登录与名单映射；内部稳定 ID 用于外键、URL、审计与日志。

### 3.3 后端分层约束

| 层 | 职责 | 禁止 |
|---|---|---|
| API Router | 路径、Pydantic Schema、鉴权依赖、状态码、错误码 | 不写业务规则、不拼 SQL |
| Application Service | 用例编排、事务边界、调用领域服务 | 不依赖具体模型厂商/前端 |
| Domain Service | 审核、组卷、关系发布、评分等领域规则 | 不读 HTTP Request |
| Repository | SQL 与持久化封装；接口与 ORM 选型无关（见 ADR-004） | 不承载跨模块流程 |
| Infrastructure Adapter | SQLite、文件、模型 Provider、G6 数据适配 | 不反向侵入领域规则 |

### 3.4 核心状态机（V1.3 要求，独立挑战 F-19 补充）

| 对象 | 状态枚举 | 合法迁移与约束 |
|---|---|---|
| 视频资源 | `uploading → processing → draft → pending → published → offline`；`failed` 可从 uploading/processing 进入，可重试 | 未 published 学生端不可访问；下架不删文件 |
| AI 任务 | `queued → running → succeeded / failed / degraded` | 超时置 failed；无 Key 置 degraded 并保留本地能力；重试幂等 |
| 考试 | `draft → published → ongoing → ended → archived` | 发布生成不可变快照；ended 后不可继续作答；归档不物理删除 |
| 审核（题目/关系） | `draft → pending → approved / rejected → archived` | 状态迁移写审核人/时间/理由；未 approved 不进学生端 |
| 名单导入 | `previewing → importing → partial_success / success / failed` | 错误行跳过、合法行入库；错误行 CSV 含行号与原因 |
| 作业提交 | `draft → submitted → resubmitted → graded → published` | 只追加版本；AI 建议不改原件 |

**通用约束**：非法迁移服务端拒绝并记录审计；所有长任务有超时与重试次数上限；相同请求重复提交幂等；状态变更写入事件表供学情与运维查询。

## 4. 技术选型与 ADR

### ADR-001 模块化单体 + FastAPI/Uvicorn
- **决策**：单机单实例 FastAPI，入口 `app.server:app`，Uvicorn 监听 `127.0.0.1:8787`。
- **证据**：P04 PoC-03 六项 PASS（**端口空闲检查、服务启动、API 路由、静态挂载、仅 loopback 可达、可停止**）。
- **后果**：不做微服务/容器编排；局域网需单独安全评审（Q2）。
- **状态**：采用（已 PoC）。

### ADR-002 原生 HTML/CSS/JS + ES Modules + A token 单一来源
- **决策**：无构建链；前端由 FastAPI 静态挂载；设计 token 只在 `styles/tokens.css` 的 `[data-scheme="A"]` 定义；师生共用，禁止 `[data-role]` 配色覆盖与非 token 色值；`prototype/baseline.html` 是唯一基线来源。
- **理由**：P04 路线 C；P05 用户确认 A + 师生统一；8/8 基线冒烟含"无角色级样式覆盖"静态校验。
- **后果**：B/C 仅留决策过程对比，不得进入交付构建（见 §5.1）。
- **状态**：采用（已确认、已冒烟）。

### ADR-003 SQLite + WAL（本机稳定磁盘）
- **决策**：活动库放本机非同步目录，启用 WAL、`busy_timeout`、外键约束；备份用一致性备份 API 或受控停写检查点；禁止放 NAS/网络共享/云同步目录。
- **证据**：P04 PoC-01 六项 PASS（8×50 并发写 400/400 无丢失、在线备份一致、中文路径 OK）。
- **后果**：写事务仍串行；出现持续锁或跨主机需求时启动 PostgreSQL 迁移评估。
- **状态**：采用（已 PoC）。

### ADR-004 ORM 与迁移：**P0 基线锁定为 sqlite3 + 版本化迁移**（独立挑战 F-03 修订）
- **决策**：P0 采用 Python 标准库 `sqlite3` + 自建 `schema_migrations` 版本表；Repository 接口与 ORM 实现解耦；迁移文件为编号升序 SQL（`0001_xxx.sql`），含 `up/down` 与校验值，执行前后记录版本与审计；SQLAlchemy 2.x + Alembic 仅作后续可选升级，不作为 P0 依赖。
- **理由**：P04 实测 ORM 未装；若把二选一拖到 P10，会推翻 P07 的 Repository 与事务边界设计。
- **P07 最小约定**：Repository 只暴露 `get/list/save/delete/transaction`，不返回裸 cursor；迁移由启动检查执行，禁止无迁移直改 Schema。
- **门禁前移**：TR-02 由 P10 前移至 **P06 定案 + P07 详设签收**；P10 仅安装依赖并复查漏洞面。
- **状态**：**已定案（设计采用，SQL 文件实现 NOT_RUN）**。

### ADR-005 图谱：G6 v5.1.1 组件级复用 + 严格渲染判据（TR-01）
- **决策**：`@antv/g6@5.1.1`（MIT，UMD）只做渲染；权威数据在 SQLite；入渲染前按稳定 ID 与关系证据去重；**禁止 v4 `graph.readData()`**；使用 `new G6.Graph({container,data,layout,animation:false})` 并等待 `render()` Promise resolve；必须显式配置 `layout`（否则画布空白）。渲染完成判据见 §5.3。
- **证据**：P04 PoC-02 严格判据复验 PASS（40 节点/40 边，Promise resolved，抽样节点绘制坐标各异，截图 `poc/shots/g6_strict.png`）；原判据假 PASS 已作为发现修正。
- **后果**：P07 必须定义节点/边唯一键与去重（§5.2）；500/1500 规模性能 NOT_RUN。
- **状态**：采用 v5（40 规模实绘；500/1500 NOT_RUN）。

### ADR-006 检索：jieba + BM25，向量库暂缓
- **决策**：P0 用 jieba 分词 + BM25 + 课程专业词典 + `judge_rejection()` 单一入口；不引入 pgvector/Chroma/Milvus。
- **理由**：jieba 已装且 0 漏洞、rank_bm25 Apache-2.0；向量库缺乏收益证据。
- **后果**：仅当新教材评测集证明 BM25 有稳定召回缺口且混合检索收益大于治理成本，才启动向量 PoC。
- **状态**：采用（库安装与效果评测 NOT_RUN，时序见 §9.2）。

### ADR-007 AI：ModelGateway + Provider Adapter + 出域闸门
- **决策**：业务模块不直连厂商；统一网关提供 text/vision Provider；每次调用记录 `provider/model/prompt_version/task/用量/状态`；无 Key 时本地能力可用并明确降级；模型输出按不可信输入做 Schema/引用/权限校验。学生材料出域逐次 D3 批准；姓名/学号、班级、成绩默认不出域。
- **状态**：架构采用；**外部联通 NOT_RUN（D3）**，P04 仅验证降级契约。

### ADR-008 权限：RBAC + 范围 + 账号状态，服务端默认拒绝
- **决策**：角色决定操作；课程/班级决定数据范围；对象归属决定个人数据；`must_change_password` 为服务端授权维度（未改密仅放行改密/退出）；账号统一表 + `account_source ∈ {admin_created, roster_import}`，禁止导入产生教师账号；身份双层（学号登录，内部 UUID 用于外键/URL/审计/日志）。
- **状态**：采用（实现与权限回归 NOT_RUN）。

### ADR-009 文件：元数据入 SQLite，本体存非 Web 根目录
- **决策**：教材/视频/图片/附件存本机受控目录；DB 存相对路径、校验值、来源/授权状态；上传做扩展名+MIME+签名+大小校验、随机文件名、鉴权下载；视频 P0 用原生 `<video>` + Range，但进度采用**分片鉴权 + 客户端心跳上报 + 大跳转重置有效区间**（见 §6），满足 VID-007"不可快进计满"。
- **状态**：采用（上传/播放/进度回归 NOT_RUN）。

### ADR-010 部署：本机 loopback 单实例（状态拆分）
- **决策**：`py -3 -m uvicorn app.server:app --host 127.0.0.1 --port 8787`；新增 `/api/health` 五态探测（应用存活、DB、目录可写、索引就绪、模型配置）。
- **状态拆分**：**loopback 部署已 PoC（P04 PoC-03）**；**`/api/health` 五态探测为设计采用（未验证，P07 详设 / P10 联调）**。

### ADR-011 内容基线：《面点工艺学》正式源 + 历史资产隔离
- **决策**：教材版本表记录 SHA-256，解析输出 `parse_report` 并教师抽检；《中国名点》及旧图谱仅做历史盘点差异报告，默认不导入；单独授权后逐项核验与审核迁移。
- **状态**：采用（教材解析与迁移报告 NOT_RUN，待 M3）。

### ADR-012 不可变快照、版本与审计
- **决策**：
  - 试卷快照**自包含深拷贝**（题干/选项/答案/解析/分值/评分要点/规则版本/知识点映射）+ 内容哈希，发布后只追加；题库修改/停用/删除不得级联破坏快照。
  - 图谱采用**发布全图快照 + `published_version` 指针原子切换**；学生端只读单一版本；回滚不物理删除历史。
  - 成绩更正/撤回事件必填操作者、时间、原值、新值、原因；学生端同步显示更正标记。
  - OPEN-11：审计与成绩链保留，个人字段可匿名化（不物理删除审计链）。
- **状态**：采用（实现 NOT_RUN）。

### ADR-013 测试契约：受控清单与实测时序

## 5. 前端架构与 A 基线落地

| 层 | 内容 | 约束 |
|---|---|---|
| shared | 导航壳、顶眉刊头、书脊、按钮/表单/表格、状态徽章、错误页、鉴权状态 | token 唯一来源 `[data-scheme="A"]`；禁止 role 级覆盖与非 token 色值 |
| student | 首页/课程/知识/图谱/视频/测评/任务/档案 | 只呈现学习主内容，无调试/账号技术字段 |
| teacher | 工作台/班级/知识/图谱/题库/出题/组卷/批改/学情/视频 | 与 student **同版式同色调**，仅导航条目与业务内容不同 |
| admin | 用户角色、模型配置、存储、备份、审计、运行状态 | 沿用 A 风格，不另起视觉体系 |
| graph | G6 v5 渲染适配、局部子图、列表降级 | 不存权威图谱数据；只接收已去重数据 |

### 5.1 A 基线防绕过规则（独立挑战 F-07 补充）

1. **交付边界**：`prototype/` 是 P05 验证资产，不进入交付构建；`index.html`（含 B/C 与 `#scheme` 切换）**不部署**。交付前端只含由 `baseline.html` 派生的 A 资产，入口不读取 `scheme` 参数。
2. **色值门禁**：除 `styles/tokens.css` 的 `[data-scheme="A"]` 外，任何 CSS/JS/HTML 不得出现 B/C 特征色值或任意硬编码颜色（P08/P10 静态检查，责任人为前端负责人）。
3. **角色门禁**：任何 CSS 不得出现 `[data-role=...]` 配色覆盖（现有基线冒烟已校验；实现期纳入同一检查）。
4. **门禁落点**：P10  CI/静态检查 + P08 UI 回归双人复核；未通过不得进入 P11。
5. 教师端 4 项与学生端 3 项指标共用 `auto-fit` 栅格，避免孤行（P05 目检已修复项）。

### 5.2 图谱稳定 ID 与去重键（独立挑战 F-09 补充）

- **节点 ID** = 实体类型前缀 + UUID（如 `KNP-<uuid>`、`CAS-<uuid>`），禁用标题/数组下标/显示顺序作为 ID。
- **边唯一键** = `(source_id, relation_type, target_id, evidence_id_or_version)`；不同证据或审核版本的多条关系合法共存。
- 去重在**领域层/SQLite 查询结果**完成；G6 只接收已去重数据，不得在渲染层做业务去重。
- `origin_graph`/`origin_id` 仅供历史资产盘点，不参与正式 ID。

### 5.3 G6 渲染完成与降级判据（独立挑战 F-01/F-10 补充）

**PASS 判据（必须全部满足）**：
1. `render()` Promise resolved；
2. `getNodeData()/getEdgeData()` 数量与请求一致；
3. 抽样节点 `getElementRenderBounds()` 返回有限边界且 `getElementPosition()` 坐标**互不相同**（证明布局已执行，非全部 0）；
4. canvas 分层存在；
5. 无 `error` / `unhandledrejection` / console error；
6. 人工目检截图可见节点与连线（小规模 PoC 阶段）。
> 禁止仅以"canvas 存在"或"数据层节点数"判 PASS——原 PoC 因此产生假 PASS。

**降级触发**：`render()` reject / 超时 5s / 实际绘制元素数不符 / console error；触发后保留搜索、列表视图与详情面板，并记录可观测事件。

## 6. 关键数据流

| 流程 | 路径 | 闸门 |
|---|---|---|
| 登录/权限 | 学号+密码 → 会话 → 角色+课程/班级范围+账号状态 → 授权首页 | 失败不泄漏账号存在性；`must_change_password` 未通过仅放行改密/退出；越权拒绝并审计 |
| 问答/拒答 | 问题 → 域外词闸门 → jieba+BM25+课程词典召回 → `judge_rejection()` → 证据上下文 → 模型/extractive 降级 → `_cite_overflow` 校验 → 回答+四级来源+覆盖率 或 教学边界通知书 | 所有入口共用单一判据；引用由服务端按证据 ID 渲染 |
| 教材知识生产 | DOCX(SHA 校验) → `parse_report` → 章节/知识单元/证据 → 教师抽检 → 发布 | 未授权不改课程知识版本；《中国名点》仅盘点 |
| AI 出题 | 教师参数 → 最小教材上下文 → 结构生成 → 质量检查 → 草稿/待审核 → 逐题审核 → 入库 | 无证据标风险；不伪造引用；审核留痕 |
| 组卷/考试 | 蓝图 → 抽题/AI 建议 → 预览校验 → 自包含不可变快照 → 作答 → 阅卷 → 成绩确认发布 → 更正/撤回留痕 | 客观题自动、主观题教师确认；补考按 OPEN-07 |
| 作业批改 | 提交版本(只追加) → AI 分项建议+依据 → 教师接受/修改/拒绝 → 终评分发布 | AI 不覆盖原件；视觉评价仅可观察证据 |
| 图谱 | SQLite 节点/边/证据/审核/版本 → 稳定 ID 与关系去重 → 局部子图 JSON → G6 v5 渲染 或 列表降级 | 先修必须教师确认；`published_version` 单一版本读取；未审核不进学生端 |
| 视频 | 上传校验 → 元数据/关联 → 预览发布 → 分片鉴权文件流+Range → 心跳上报有效观看区间 → 本人进度 | 大跳转重置当前连续区间；累计有效观看 <90% 显示未完成；未发布不可访问 |
| 学情 | 各模块事件 → 统一事件服务 → 按课程/班级/窗口聚合 → 展示样本数/口径/更新时间 | 无模拟数据混入；导出默认不含学号/姓名 |
| 名单导入 | 上传 → 预校验 → 预览/字段映射 → 部分成功事务 → 错误行 CSV（行号+原因）→ 审计 | 重复学号不静默覆盖；错误行不入库；导入账号 `account_source=roster_import` |

### 7.2 故障与降级矩阵

| 故障 | 系统行为 | 可验证条件 |
|---|---|---|
| 无 Key / 模型不可用 | 本地问答、规则/模板出题、组卷、图谱浏览可用，明确降级提示 | 断网/无 Key 下核心本地流程可跑；提示可见 |

| 视频上传失败 | 拒绝并说明原因，不产生可播放假资源 | 伪装格式/损坏/超限被拒 |
| 考试超时/刷新/重启 | 保留已作答，规则内续答或明确失败态 | 超时自动交卷、重复提交幂等 |

| 越权访问 | 服务端拒绝、错误码 `PERM_*`、审计记录 | 学生越权/教师跨班级越权均被拒且有记录 |

## 8. 安全、隐私与账号边界

### 8.1 身份与授权（独立挑战 F-11/F-12/F-13 补充）

- **身份双层**：`users.id`（内部 UUID）用于外键、URL、审计、日志；`student_no`（学号）仅用于登录与名单映射，不出现在 URL/日志/导出（除非单独授权并留痕）。
- **账号来源**：统一账号表 + `account_source ∈ {admin_created, roster_import}`；导入只产生学生账号；教师账号由管理员创建。
- **密码状态**：`must_change_password` 为服务端授权维度；未改密不返回个人档案与成绩。
- **权限五维**：角色 + 课程范围 + 班级范围 + 对象归属 + 资源发布状态；默认拒绝。
- **审计最小字段**：操作者内部 ID、角色、时间、动作、对象、结果、理由（敏感访问必填）；不记学号明文。
- **OPEN-11 路径**：审计链与个人成绩记录保留，个人标识可匿名化，不物理删除审计链。

### 8.2 日志与可观测性脱敏（独立挑战 F-08 补充）

| 类别 | 可记录 | 禁止/处理 |
|---|---|---|
| 应用日志 | request_id、模块、级别、错误码、耗时、异常类型 | 不记请求体原文、密码、完整学生提交内容 |
| 审计日志 | 操作者内部 ID、角色、动作、对象、前后状态摘要 | 不记学号/姓名明文 |
| AI 调用日志 | 任务、Provider/Model、Prompt 版本、耗时、用量/费用、状态 | 不记 Key、未脱敏个人数据、原始材料全文 |
| 错误堆栈 | 类型 + 脱敏摘要 | 不把含 Key/个人信息的异常消息原文落盘 |
| 留存 | 按策略轮转 | 审计不被普通日志清理删除 |

### 8.3 Web 安全与 D3
- **CSRF/CORS**：Cookie `SameSite=Strict`；写请求统一校验自定义 header 携带的 CSRF token；CORS 白名单仅 `http://127.0.0.1:8787`（不保留 `*`）；同源优先。
- **XSS/SQL/文件**：输出按上下文编码；参数化查询；上传白名单+签名+随机名+鉴权下载。
- **D3 人工批准**：教材授权发布、模型供应商/预算、学生材料出域、局域网开放——架构不代为批准。
- **开源合规**：记录 URL/版本/Commit/SPDX/引入方式/修改记录；NOASSERTION 项目 P0 不引入；依赖锁具体版本。
