### 需求状态标记

| 标记 | 含义 | 处理规则 |
|---|---|---|
| MUST | 必须实现，P0 核心交付 | 必须有可测试、可演示、可验收的实现；未通过不得标记完成 |
| SHOULD | 应当实现，P1 增强 | 预留数据模型与接口，不挤占 MUST 关键路径 |
| COULD | 可实现，P2 探索 | 本阶段不承诺交付 |
| OUT | 明确不做 | 本阶段范围外，不得擅自扩大 |
| OPEN | 待确认 | 依赖学校制度/教师习惯/预算/授权；对应模块开发前确认，未确认不得编造 |

## 1. 产品概述与建设背景

### 1.1 产品背景

一阶段以课程专属知识问答和可演示教学能力为目标，形成了教材解析、检索问答、证据引用、分步实训、配方换算、问题诊断、案例图鉴、知识图谱及多模态实训等能力。二阶段目标从"演示正确性"转向"真实教学场景可用"，补齐账号与课程班级、学习记录、教师审核工作台、题库考试、作业批改、视频资源与班级学情分析。

**一阶段数字基线**（2026-11-12 总结报告口径，仅用于历史资产盘点，**不是** V2.0 正式知识库目标数量）：知识单元 2,406（课程 893、案例 1,513）；案例标题 254，字段完整可实训 181、可配方换算 179；图谱两套互不兼容（`/api/graph` 408 节点/1,342 边，`/starmap` 227 节点/236 关联）。

### 1.2 产品名称与课程/教材口径（PRD-CR-001 / PRD-CR-004 修订）

| 口径项 | V2.0 结论 |
|---|---|
| 唯一正式教材基线 | `docs/面点工艺学.docx`，SHA-256 `5a857b6f3bdd0436de9202543dde0e6a55e5775a9b22ab13bcf472450dd42e22`。M3 解析前须复核校验值与授权范围。 |
| 《中国名点》相关资产 | 全部降级为**历史迁移资产**（章节、840 词词典、254 案例、204 drills、两套图谱），不进入正式知识库；如需复用须逐项核验并单独授权。 |
| 课程显示名称 | 由教师/学校在课程管理中配置，**不预设、不等于教材名称**。系统初始可为空白或"待配置"状态。 |
| 专业/学期/班级 | 同为配置项，运行时录入；教学大纲若后续提供，作为元数据录入，不反向改代码。 |

> 【Unwanted】如果任何模块把教材名称或文件名当作课程正式名称，或把《中国名点》历史数据当作当前课程的正式知识，则系统应阻止该发布并在审核记录中标为不合规。

### 1.3 产品定位

问面 V2.0 是以专业课程知识为核心、以 AI 辅助教学为手段、以教师教学工作流为主线的课程专属智能教学平台。服务教师备课、资源组织、知识讲解、出题组卷、考试测评、作业批改与学情复盘；服务学生课程学习、知识导航、案例学习、实训训练、练习测评与学习反馈。首轮为**本机多角色模拟验收**（PRD-CR-003）。

### 1.4 设计原则（PRD-CR-002 修订：能力契约继承 vs 代码资产不继承）

| 原则 | 说明 |
|---|---|
| 课程专属 | 聚焦《面点工艺学》教材及对应课程，不把跨专业/跨课程泛化作为 MUST。 |
| 可信优先 | AI 回答、题目、图谱关系、视频章节与评分建议均须有来源、状态与审核责任人；未经确认的 AI 结果不得伪装成教材事实。 |
| 教师主导 | AI 辅助而**不替代**教师对教学内容、正式题目、主观题评分与实训成绩的最终决定；不做 AI 自动发布成绩。 |
| 学生易用 | 优先搜索、目录、清晰任务流程与可理解反馈，不把复杂图谱画布作为唯一入口。 |
| 可追溯 | 知识、题目、作业、评分、视频资源均能关联课程、章节、知识点与来源。 |
| **能力契约继承、代码资产重建** | **继承的是"行为契约与验收门槛"**：拒答单一判据、42 样本/8 入口/71 场景能力基线、引用闸门、四级溯源、配方确定性计算——这些必须在 V2.0 中**重新实现并通过同等或更严格的验证**；清单与判定口径须在 P08 锁定为受控附件（详见 STU-005）。**不继承的是"代码/页面/数据资产"**：`wenmian_buddy` 的源码、页面、JSON/DB 数据、旧词典、旧图谱一律不导入；视觉风格可延续同类设计语言，但不得复制原页面代码或组件文件。 |
| 本机优先 | 开发、部署与首轮验收以本机为基线；局域网/公网发布不在本 PRD 承诺范围内。 |
| 成本可控 | 模型调用按任务配置、限额、记录与降级；不默认无限调用外部 API。 |

> 【Unwanted】如果开发任务以"继承一阶段"为由直接复制 `wenmian_buddy` 的代码、页面或数据文件，则应视为违反 P00-A1，退回并改为按本 PRD 重新实现。

## 2. 产品定位、目标与成功指标

### 2.1 核心目标

| 编号 | 目标 | 产品结果 |
|---|---|---|
| G-01 | 让学生理解课程知识结构 | 可搜索、可浏览、可关联的课程知识图谱与知识详情 |
| G-02 | 提升自主学习与实训能力 | 教材问答、案例学习、分步实训、配方换算、诊断、视频、练习形成闭环 |
| G-03 | 减少教师重复工作 | 教师管理资源、AI 辅助出题、组卷、审阅、批改与学情复盘 |
| G-04 | 提高题目与评价质量 | 题目关联知识点、来源、答案与评分规则；AI 生成内容经教师审核 |
| G-05 | 形成可持续教学数据资产 | 课程、班级、学习记录、考试、作业、视频与成绩可追溯 |
| G-06 | 保留可信能力 | 在新工程中重新实现并通过拒答、引用、溯源、确定性计算与回归门槛 |

### 2.2 成功指标与测量方法

| 维度 | 指标 | 测量方式 | 目标口径 |
|---|---|---|---|
| 功能完整性 | MUST 需求通过率 | 按需求 ID 执行验收用例 | 所有 MUST 通过；未通过项不得标记完成 |
| 知识可信 | 引用可回溯率 | 抽样检查回答引用能否定位教材章节/条目/案例 | 标记有来源的回答均可回溯；无证据时拒答或提示 |
| 图谱质量 | 关系证据覆盖率 | 抽查关系来源、类型、审核状态 | 正式发布关系具备来源与类型；AI 建议不直接发布 |
| 出题质量 | 题目审核通过率/缺陷率 | 教师审阅生成题并记录问题类型 | 先建基线再由教师设阈值；不以模型自评代替 |
| 批改质量 | AI 建议与教师终评分差异 | 抽样双评统计差异 | 先小样本校准；AI 评分仅为建议 |
| 易用性 | 关键任务完成率 | 教师/学生完成搜索、建题、组卷、批改、找视频等任务 | 关键任务无需开发介入；记录完成率与卡点 |
| 成本 | AI 调用量与费用 | 按模型、任务、用户、日期统计 | 项目负责人确认预算上限；阈值告警或停止非必要调用 |

> 具体百分比、试点人数、周期与 API 月度预算尚未确认（OPEN-06）。本 PRD 不虚构数值，先规定测量口径与验收机制。

## 3. 建设范围与优先级

### 3.1 MUST（P0 首批必须交付）

| 领域 | MUST 范围 |
|---|---|
| 平台基础 | 本机运行、账号/角色、课程班级数据结构、学生名单导入（学号唯一）、持久化、备份恢复、操作审计 |
| 学生学习端 | 课程首页、目录、知识详情、图谱浏览、教材问答与溯源、案例图鉴、分步实训、配方换算、问题诊断、视频学习、练习考试、个人学习记录 |
| 教师工作台 | 教师首页、课程班级、资源、图谱管理、题库、AI 出题与审核、手动/规则/AI 辅助组卷、考试发布与成绩、作业发布/审阅/批改、实训评分标准、学情分析基础视图 |
| 知识图谱 | 统一节点/关系模型、来源与审核状态、三栏交互、搜索筛选展开详情关系路径、教师关系审核 |
| 视频资源 | 教师上传、元数据、课程/知识点/案例关联、预览播放、发布/下架、访问权限、观看记录 |
| AI 治理 | 模型适配层、Prompt 版本、任务限额、失败降级、证据约束、人工审核、调用日志 |

**MUST 需求编号与数量**：FND-001~010（10）+ STU-001~014（14）+ TCH-001~018（18）+ KG-001~014（14）+ VID-001~007（7）+ NFR-001~012（12）= **75 项**（见 §18.1 追踪矩阵）。

### 3.2 SHOULD（P1 增强）

AI 字幕生成、视频章节自动识别、视频片段与知识点自动关联（教师审核后发布）；互动视频（时间点插题、提示、形成性测验，评估 H5P 组件）；语义检索与 BM25 混合检索（是否引入向量库按评测决定）；更完整学习路径推荐、错题本、个性化复习计划；视频转码队列、HLS 自适应播放、MinIO/S3 存储适配；批量导入导出、批量审核、更多题型与复杂评分量表。

### 3.3 COULD（P2 探索）与 OUT（明确不做）

**COULD**：跨课程内容关联分析、教师 AI 备课助手扩展、学习成效预测模型。本阶段不承诺交付。

**OUT（本阶段明确不做）**：原生 iOS/Android App；语音问答；AI 生成面点成品图片替代真实工艺证据；开放式学习社区/UGC；跨专业/跨学院/跨学校平台化；自动知识图谱事实推理或未经教师确认的智能推荐；自动替教师确认主观题/实操/最终成绩；在线监考、人脸识别、屏幕监控；公网正式运营与云端长期保存完整教材/学生原始视频；导入 `wenmian_buddy` 的代码、页面与数据资产。

### 3.4 部署边界（PRD-CR-003 修订）

| 项 | V2.0 结论 |
|---|---|
| 首轮验收 | 本机 `127.0.0.1:8787`，多浏览器/多账号模拟教师+学生完整流程 |
| 局域网/公网 | 不开放；任何多设备访问须另行评审并升 R3 |
| 风险等级 | 保持 **R2**（本地持久化、学生个人信息、可选外部 AI、文件上传） |
| 扩展能力 | 数据模型具备多课程/多班级/多角色扩展能力，但不据此宣称首轮已支持多设备课堂 |

| 约束 | 断网时本地内容/题库/图谱/视频可用；不开放局域网监听 | NFR-001 / Q2 |

## 4. 用户角色与权限边界

| 角色 | 主要职责 | 主要权限 | 禁止事项 |
|---|---|---|---|
| 学生 | 学习、查看知识、问答/实训、练习考试、提交作业、观看视频 | 查看已授权课程内容；查看本人记录/反馈/成绩；提交本人作业 | 不得查看他人成绩、教师答案、未发布题目与内部审核内容 |
| 教师 | 管理课程资源、题库、试卷、考试、作业、评分与学情 | 管理授权课程/班级；创建编辑审核资源；出题组卷；发布任务；审阅确认成绩 | 不得越权访问其他课程/班级；AI 建议未经确认不得作为最终成绩 |
| 课程负责人/审核人 | 审核知识、标准工艺、题目与评分量表 | 授权课程内审核知识关系、教学标准、题库与评分规则 | 不得修改系统安全配置或查看非授权个人数据 |
| 系统管理员 | 本机配置、账号、角色、备份、日志与运维 | 管理用户、角色、系统配置、存储、模型接口与审计 | 敏感业务数据访问遵循最小权限并留审计 |

### 4.1 权限原则（EARS）

- 【Ubiquitous】系统应始终采用角色权限与课程/班级数据范围双重控制：角色决定能做什么，授权范围决定能对哪些数据做。
- 【Ubiquitous】系统应在服务端执行所有权限校验；前端隐藏按钮不算权限控制。
- 【Event-driven】当教师尝试访问未授权课程/班级时，系统应拒绝该访问并记录审计。
- 【State-driven】在未登录或会话失效状态下，系统应给出清晰登录入口与恢复路径，不得只显示裸错误码或空白加载态（PRD-CR-007）。
- 【Ubiquitous】成绩、考试答案、作业附件、学生提交文件、**学生学号与姓名**属于受控数据；导出与日志默认不含学号/姓名，除非单独授权并留痕（P03-S15）。
- 【State-driven】在成绩已发布状态下，学生应可查看本人成绩与教师评语；教师答案、未发布题目与内部审核内容在任何状态下均不向学生开放；发布后新增的公开内容范围由教师在发布时显式选择（P03-S17）。
- 【Ubiquitous】管理员可访问用户/角色/配置/存储/模型接口/审计等运维数据；不得无审计地直接读取或导出学生作业原文、原始视频与成绩明细，确需访问应记录理由并留痕（P03-S16）。
- 【Event-driven】当发生发布考试、发布作业、确认成绩、修改已发布题目、删除资源、权限修改等关键操作时，系统应记录操作者、时间、对象与变更内容。
- 【Optional】在学校统一身份认证环境下，系统可另行对接；P0 仅本地账号。

## 5. 核心业务流程

| 流程 | 步骤 | 关键门禁 |
|---|---|---|
| 5.1 学生学习闭环 | 进入课程 → 选章节/搜索知识点 → 阅读知识详情及教材来源 → 查看关联案例/视频 → AI 问答或分步实训 → 完成练习/作业/考试 → 查看反馈与薄弱点 → 回到知识详情或推荐资源 | 来源可回溯；无证据拒答；只展示已发布关系与视频 |
| 5.2 教师备课闭环 | 进入工作台 → 选课程/班级 → 查看知识与资源 → 维护知识节点/关系（必要时审核 AI 建议）→ 从题库选题或 AI 生成候选 → 审阅入库 → 按蓝图组卷 → 预览 → 发布考试 → 阅卷 → 成绩确认发布 → 学生查看 → 必要时更正/撤回（留痕） | AI 候选题先审核；发布前强制预览与总分校验；成绩更正/撤回须留痕；补考/重考/迟交规则见 OPEN-07（考试模块开发前门禁） |
| 5.3 作业批改闭环 | 创建作业 → 设提交类型/截止/评分量表 → 选班级发布 → 学生提交文本/文件/图片/视频 → 校验提交状态 → AI 生成建议及依据 → 教师逐份审阅修改确认 → 发布成绩与反馈 → 归档 | 原始提交不可被 AI 覆盖；教师确认才发布 |

| 5.5 视频发布闭环 | 教师上传 → 完整性/格式检查 → 保存原件与元数据 → 生成预览信息 → 关联课程章节/知识点/案例 → 教师预览 → 发布 → 学生观看记进度 | 未发布/下架不可被学生访问；原件保留 |

## 5.6 异常处理总表（P03-S09 补充）

| 异常场景 | 系统行为（EARS） | 可验证条件 |
|---|---|---|
| 登录失败（错误密码/账号不存在） | 【Unwanted】如果登录失败，则系统应给出不泄漏账号存在性的统一提示，不说明是账号还是密码错误。 | 错误密码提示与不存在账号提示文案一致；不回显账号来源。 |
| 登录失败次数超限 | 【Unwanted】如果连续失败达到配置阈值，则系统应临时锁定该账号并提示解锁方式。 | 阈值可配置（默认待责任人确认）；达阈值后正确密码也被拒；锁定时长与解锁路径可验证。 |
| 忘记密码 | 【Unwanted】如果学生忘记密码，则系统应提供由教师/管理员重置的线下路径，不提供自助邮件/短信找回（P0 范围）。 | 教师重置后学号+新密码可登录；旧密码失效。 |
| 会话失效/未授权 | 【Unwanted】如果会话失效或未授权访问，则系统应渲染含登录入口与恢复路径的可理解页面。 | 不出现裸 `AUTH_REQUIRED` + 空白"加载中…"（PRD-CR-007）。 |
| 名单导入冲突 | 【Unwanted】如果导入遇到重复学号或字段错误，则系统应采用部分成功策略：跳过错误行、继续导入合法行，并给出整批反馈与可下载错误行。 | 合法行入库、错误行不入库；错误行文件含行号与原因；无静默覆盖。 |
| AI 调用失败/超时 | 【Unwanted】如果模型不可用，则系统应保留本地能力并给明确降级提示，不伪造 AI 结果。 | 断网/无 Key 下本地问答与规则出题可用；失败提示可见；调用日志有失败记录。 |
| 考试异常（超时/刷新/服务重启） | 【Unwanted】如果考试过程中发生超时、页面刷新或服务重启，则系统应保留已作答内容并允许在规则内续答，或给出明确失败状态。 | 超时自动交卷；重复提交幂等；刷新后作答可恢复；断点策略在 P07 详细设计确定。 |
| 视频上传失败 | 【Unwanted】如果上传损坏/伪装格式/超限文件，则系统应拒绝并说明原因，不产生可播放假资源。 | VID-002 校验生效；失败资源不出现在列表；原件保留策略有效。 |
| 数据加载失败 | 【Unwanted】如果页面数据加载失败，则系统应显示原因与重试入口，不长期停留"加载中…"。 | 断网/接口错误下可见失败提示与重试按钮。 |

> 本节为 P03-S09/S12 要求的统一异常处理清单；各模块细节以 §7 需求与 P07 详细设计为准。

**布局硬约束（回应 P00 四张截图）**：

- 【Ubiquitous】学生学习端首页应只呈现学习相关主内容；调试信息、账号技术字段、示例快照不得混入学习主界面。

## 8. 知识图谱专项需求

### 8.1 重构原因与目标（PRD-CR-001 修订）

一阶段存在两套互不兼容图谱（`/api/graph` 408 节点/1,342 边；`/starmap` 227 节点/236 关联），关系主要来自同章共现与教材顺序推导，不能直接解释为教师确认的先修/因果。二阶段应统一数据模型与发布口径，旧图谱仅作迁移候选。

> 【Unwanted】如果旧图谱关系未经逐项审核，则系统不得将其标为权威知识关系（PRD-CR-002：旧图谱属不导入的历史资产，仅在人工核验后可迁移结构化事实）。

### 8.2 节点类型（PRD-CR-001 修订：示例改为《面点工艺学》语境）

| 节点类型 | 说明 | 示例（面点工艺学语境） |
|---|---|---|
| 课程 | 课程实例或主题 | 由教师配置的课程显示名（非教材名） |
| 章节/节 | 教材组织结构 | 面点工艺学某章某节 |
| 知识点 | 可独立教学测评的知识单元 | 水调面团的性质 |
| 原料/工具/设备 | 工艺相关对象 | 面粉、水、擀面杖 |
| 工艺/操作步骤 | 制作方法、工艺环节与操作动作 | 和面、揉面、成型 |
| 案例/成品 | 典型面点案例与成品 | 教材中的面点案例 |
| 题目/题组 | 题库与测评资源 | 水调面团单选题 |
| 实训任务/评价标准 | 可执行训练与评价规则 | 分步实训任务 |
| 视频/课件/资源 | 教学媒体资源 | 教师上传的操作示范视频 |

### 8.3 关系类型与发布要求（不变）

包含/隶属（依课程结构或教材目录生成校验）；教材来源于（必须保存来源定位）；相关知识（注明依据、教师审核后发布）；先修于（必须教师确认，不得仅凭教材顺序推断）；应用于/体现于（必须有教材或教师证据）；使用/依赖（需来源或教师确认）；评测/训练（关联正式版本）；配套资源（资源已发布且权限有效）。

### 8.4 图谱验收原则

同一知识点在课程树、详情、题库、视频与图谱中使用统一标识；所有正式关系有类型、来源与审核状态；教材章节先后不自动等同于先修；学生端只展示已发布关系；三维星图可作为可选总览但非默认入口。

## 9. 题库、组卷、考试与作业专项规则

### 9.1 题型与评分（不变）

单选/多选/判断/填空/简答/论述案例分析/图片文件题为 P0 支持；实操视频题基础支持（不承诺动作级自动评分）。多选题部分得分由教师配置不自动推断；填空复杂语义转人工复核；主观题 AI 仅建议、教师确认。

### 9.2 题目生命周期

草稿 → 待审核 → 已审核/可用 → 已入库 → 已引用到试卷 → 停用/归档。题目被引用后试卷必须保存快照；题库题目后续修改不影响已发布考试。

### 9.3 题目必备字段（不变）

身份与内容（ID/题干/题型/选项/附件/标签/版本）；教学映射（课程/章节/知识点 ID/教学目标/认知层次）；答案与评分（标准答案/解析/评分要点/分值/部分得分规则/同义答案）；可信来源（教材来源定位/教师来源/AI 标记/模型与 Prompt 版本）；管理状态（难度/审核状态/审核人/时间/创建者/更新时间/停用原因）。

### 9.4 AI 出题质量检查（不变）

教材范围、答案一致性、歧义、选项质量、重复（仅提示不自动删）、难度与认知层次建议、来源检查（无教材证据须标教师补充/待核实，不得伪造引用）。

### 9.5 组卷与试卷蓝图（不变）

支持手动/规则/AI 辅助组卷；规则至少按章节/知识点、题型、难度、题量、分值、总分约束；AI 辅助组卷只用已审核题或明确标识待审核候选。蓝图字段：考试范围、题型分布、难度分布、知识覆盖、总分与时长、抽题规则、版本快照。

### 9.6 考试发布与阅卷（不变）

发布前强制预览与总分/题状态/对象/时间校验；发布后不可变快照；支持开放/截止时间、时长、尝试次数、随机题序/选项、提交确认；客观题自动评分、主观题教师确认；异常（超时/重复提交/刷新/服务重启）须有可恢复或明确失败状态；P0 不建高强度监考。

### 9.7 作业发布与提交（不变）

作业类型、提交形式（格式白名单与大小上限配置化）、截止与迟交、重交（保留版本）、评分量表、反馈、复核（P0 教师重开/更正留痕，正式申诉流程 OUT）。

### 9.8 AI 辅助批改（PRD-CR-005 相关）

AI 按量表逐项给建议分与依据；不改原始提交、不覆盖教师评分；教师可接受/修改/拒绝 AI 建议（P03-S22）；图像视频评价须标可观察证据与不可判断部分，不凭视觉推断口味/香气/内部组织；高风险工艺/安全内容须课程依据或教师审核；保存 AI 批改版本与模型/Prompt 版本。

## 11. AI 能力与可信治理要求

### 11.1 AI 能力边界（不变）

课程问答（基于教材与授权知识，展示来源，证据不足拒答）；图谱建议（候选实体/关系/别名+来源片段，不自动发布）；AI 出题（候选题，未审核不入正式库）；AI 组卷（按蓝图，不绕过审核）；AI 批改（分项建议，不自动发布主观/实操成绩）；视频分析（P1 候选，不直接当标准）；学情分析（真实数据，样本不足标注）。

### 11.2 模型接入与数据出域（PRD-CR-005 修订）

| 项 | V2.0 结论 |
|---|---|
| 接入范围 | 用户已确认文本+视觉模型均接入，用于出题/批改/图谱建议/视觉能力。 |
| 适配层 | 业务模块不绑定单一厂商；按任务配置模型，名称/版本/参数/Prompt 可追踪。 |
| 供应商与预算 | 配置项，基线不写死未经确认数值；须设硬上限与用量记录，达阈值告警并停非关键调用。 |
| 教材片段出域 | 允许，但只发完成能力所需最小化文本上下文，脱敏并记录。 |
| 学生材料出域 | 学生作业图片/视频属高风险，**每次实际启用前单独 D3 人工批准**；姓名/学号、班级名单、成绩默认不出域。 |
| Key 安全 | 仅存本机受保护配置，不进前端/Git/日志/导出包。 |
| 降级 | 【Unwanted】如果无 Key 或模型不可用，则系统应保证本地检索问答、规则/模板出题、组卷、图谱浏览能力可用并给明确降级提示。 |
| 输出处理 | 模型输出视为不可信输入，须结构校验、引用校验、内容安全检查与权限过滤。 |

### 11.3 能力契约继承（PRD-CR-002 修订）

- 【Ubiquitous】系统应在新工程中重新实现 `judge_rejection()` 单一拒答判定入口，并执行 42 样本/8 入口/71 场景能力行为契约基线回归。
- 【Ubiquitous】接口与探针一致性、问答入口一致性按上述基线执行；其样本/入口/场景清单与判定口径须在 P08 测试方案中锁定为受控附件并标版本（P03-S04），清单未锁定前相关条目不得判 MUST 通过。
- 【Ubiquitous】系统应实现四级溯源、覆盖率提示、引用越界拦截与视觉硬闸门（能力行为契约，在新工程中重新实现并验证）。
- 【Ubiquitous】配方换算关键数字应由确定性程序完成，不交由大模型自由计算。
- 原有分步实训、诊断、案例图鉴、星图与视觉模块按能力契约重新实现，不复制旧代码与数据。

## 13. UI/UX 交互规范（PRD-CR-007 修订）

### 13.1 总体交互原则（不变）

主流程优先（学习/出题/组卷/批改/视频发布有明确步骤指引与完成状态）；减少跳转（侧栏/抽屉上下文跳转）；搜索优先；状态可见（文字+图标表达草稿/待审核/已发布/失败等）；批量操作二次确认并显示影响范围；不只依赖颜色；错误可恢复（明确原因与恢复路径）；响应式（桌面优先，学生端主要任务兼容移动）。

### 13.2 首页与会话状态（新增，回应 P00 截图）

| 区域 | 要求 |
|---|---|
| 学生学习首页 | 【Ubiquitous】只呈现学习主内容；调试/账号技术字段、示例快照不得混入。 |
| 教师工作台首页 | 【Ubiquitous】按授权汇总待办；学生端与教师端导航分离。 |
| 会话失效/未授权 | 【Unwanted】渲染含登录入口与恢复路径的可理解页面，不得只输出 `AUTH_REQUIRED` + 空白"加载中…"。 |
| 加载/失败态 | 【State-driven】加载中有指示；加载失败显示原因与重试，不长期停留"加载中…"。 |

### 13.3 图谱页面布局（不变）

左侧课程树/搜索/筛选（可折叠）；中央关系画布（缩放/拖动/展开收起/高亮/重置）；右侧详情（定义/来源/关系/资源，可返回）；顶部工具区（视图/层级/关系筛选/路径，显示当前条件并可清空）。

### 13.4 题库/组卷/批改交互（不变）

题库为"筛选栏+列表+详情/编辑面板"，AI 出题走参数设置→生成候选→质量检查→逐题审核→批量入库，不只有聊天式生成；组卷为左题库筛选+中试卷结构+右蓝图统计，拖动之外提供键盘上移/下移；批改为提交内容区+AI 建议区+量表区+教师评语区，AI 建议与终评分明显区分，保存草稿与发布分离。

### 13.5 设计系统（PRD-CR-002 限制）

【Optional】可延续一阶段同类视觉语言（颜色/字号/间距/按钮/卡片/导航/骨架屏的**风格**），但不得复制 `wenmian_buddy` 的页面代码或组件文件；新增教师工作台统一视觉语言。

| 学习事件 | 学生在课程中的学习、练习、观看、实训与提交行为记录。 |
| 课程专属 | 知识库、词典、案例、实训与规则以《面点工艺学》及教师确认内容为边界。 |
