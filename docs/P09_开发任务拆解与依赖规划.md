## 1. 拆解原则与共享边界

### 1.1 纵向切片原则

每个 P11 任务必须在一个切片内完成「数据库迁移 → 领域/应用服务 → API/Pydantic 契约 → A 基线前端 → 接口联调 → 自动化用例 → 可运行验证」。**不允许**连续写多个模块的数据库后才第一次联调。每个任务完成后必须能独立启动并演示该切片。

### 1.2 共享核心文件冻结规则（防止多任务并行改同一核心文件）

| 路径 | 归属 | 规则 |
|---|---|---|
| `pyproject.toml` / `requirements.lock` / `AGENTS.md` / `config/*.toml` | TASK-P10-01 独占 | P10 后冻结；后续任务只读，配置新增走独立配置文件 |
| `app/common/**`（errors/responses/db/logging/security/config） | TASK-P10-01 建立 | P10 后冻结；**仅 TASK-B01 允许补写 `app/common/security.py` 的会话查询段**，之后永久冻结 |
| `web/styles/tokens.css` | TASK-P10-01 从 `prototype/baseline.html` 派生 | 只保留 `[data-scheme="A"]`；其他任务禁止新增色值或 `[data-role=...]` 配色 |
| `migrations/` | 各任务独占新文件 | 只追加编号 SQL（含 up/down + SHA-256），禁止修改已执行迁移 |
| `app/<module>/**` | 对应任务独占 | 跨模块只读 Repository 接口，不直连他模块表 |
| `tests/<slice>/**`、`reports/<task>/**` | 对应任务独占 | 测试证据按任务归档，便于 P12/P13 复现 |
| `prototype/index.html`、`prototype/styles/schemes.css` | **不进入交付** | 含 B/C 分支，构建与部署目录禁止出现；静态门禁 G1–G10 拦截 |

### 1.3 依赖表示

`A → B` 表示 B 必须在 A 交付并验证后开始。所有任务共同依赖 TASK-P10-01（工程初始化与静态门禁），不再逐个重复写明。

## 5. 并行与冲突控制

1. **同一时刻只允许一个任务修改共享核心文件**；规则见 §1.2。B01 是唯一例外窗口。
2. **迁移文件按任务编号追加**，禁止回改已执行迁移；两任务不得共用同一 `000N_` 编号。
3. **数据库跨模块只读**：例如 Q01 需要知识点时通过 `app/know` Repository，不写 SQL 直连 `knowledge_units`。
4. **前端只从 A 基线派生**：每个任务页面必须复用 `ed-*` 类名；新增视觉体系视为缺陷，不是风格创新。
5. **联调门禁**：B03、A01、Q02、G01、T01 是五个必须现场演示的联调点；前一点未通过不得开始后续依赖任务。
6. **BLOCKED 任务的可执行部分**：A01/A02 可跑本地降级用例，但不得用降级结果替代外部模型联通；STU-005 相关回归在三清单 CONTENT_LOCKED 前不判通过；KG-014/NFR-007 在 P13 阈值固化前不判 MUST 通过。
